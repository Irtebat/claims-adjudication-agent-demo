  B2b — money-safety invariants are now validated AND threshold-checked on BOTH
        candidate AND prod in evaluate_gate. An invalid (missing/NaN/+inf/out-of-range)
        or sub-threshold @prod safety metric now fails closed and blocks promotion;
        previously prod was consulted only for the quality comparison. Added prod-side
        gate tests + a non-dry-run orchestration test asserting the alias is NOT moved
        when a prod money-safety metric is invalid.

Updated after re-review (one precision BLOCKING fix):
  B2c — money-safety threshold check is now STRICT (value >= threshold, no EPS) on both
        candidate and prod, so a value a hair below threshold (e.g. 1.0 - EPS/2) fails.
        EPS tolerance is retained ONLY in the relative quality "not worse than @prod"
        comparison. Added a just-below-threshold candidate test (gate rejects) and an
        exact-threshold test (gate still passes).
